Operations dashboard metrics explained

What each section and number on the Admin Operations Dashboard mockup means, how it should be calculated when wired to the live app, and what a placement officer should do with it.

UI spec: admin_placement_dashboard_mockup.html · Audience: Placement Officers (not Super Admin) · All student/application data scoped to admin assignments

Why this dashboard (vs old Admin Home)

The mockup is operations-first: who needs help today, what drives are live, what interviews are coming up. Analytics (school radar, MoM tables, placement-rate trends) belong on Super Admin, not here.

Section order: Scope → Pool overview → Today's snapshot → Funnel → Attention → Drives → Interviews → Activity → Pending recruiter.

Scope

Dashboard scoped to your assignments

Three-column strip listing every School, Center, and Batch the admin is assigned to. Supports multiple values per dimension (not a single school/center/batch chip).

Live source: getAdminScopeFilter() — allowedSchools, allowedCenters, allowedBatches on the admin profile.

Every metric below must respect this scope (except Job Postings — see Pool overview).

Pool overview — 4 cards (row 1)

Context numbers. Shown before Today's snapshot in the mockup. White cards with left accent border.

Job Postings

Count of posted jobs institution-wide.

Formula: jobs where isPosted = true OR status = POSTED

Not scoped to admin's students — global count

Active Students

Students in admin scope with account status = ACTIVE.

Subtitle: “In your scope · account active”

Pending Queries

Student support tickets awaiting response.

Formula: studentQuery with status IN (OPEN, PENDING, UNRESOLVED), filtered to scoped students.

Applications

Total application rows from students in admin scope.

Formula: application.count({ student: scope })

Today's snapshot — 3 gradient KPIs (row 2)

Primary daily-action metrics. These matter more than Pool overview for “what do I do right now?”

Unplaced Students

How many students still need a placement.

Formula: eligible active students in scope − students with JOINED (or SELECTED/OFFERED/ACCEPTED) placement

Subtitle: “Eligible minus joined”

Active Drives

Job postings live right now in scope.

Formula: posted + active jobs relevant to scoped students/batches

Subtitle: “Open or interviewing now”

Interviews This Week

Scheduled interviews for scoped students in the current Mon–Sun week.

Formula: count of applications with interviewDate in current week; should match Interview schedule table row count.

Chart

Placement funnel

Pipeline drop-off within scope. Badge shows X eligible (top stage count). Each bar shows count + % of eligible for stages after Eligible.

Eligible — active students in scope

Applied — unique students with ≥1 application

Shortlisted — applications past screening / shortlisted

Interviewed — applications with interview status set

Offered — OFFERED / SELECTED / ACCEPTED

Joined — students with JOINED status

Admin action: Find the largest drop between consecutive stages — intervene there.

Table

Students requiring immediate attention

Eligible, not placed, low application count. Sorted by fewest applications first.

Column Meaning
StudentFull name
ApplicationsTotal apps submitted — low = at risk (right-aligned in UI)
Last ActivityTime since last profile or application update
Risk Level High ≤1 app · Medium 2–3 · Low 4+
Table

Currently active drives

Per-drive ops within scope. Subtitle: “Daily drive management within your scope”.

Column Meaning
CompanyRecruiter / company name
RoleJob title
ApplicationsStudents who applied (numeric, right-aligned)
ShortlistedApplications past screening
Interview DateDrive or next interview date
StatusOpen · Interviewing · Closed
Table

Interview schedule

Upcoming interviews this week for scoped students. Empty state: “No scheduled interviews this week.”

Column Meaning
StudentStudent name
CompanyInterview company
Interview TypeTechnical · HR · Technical + HR, etc.
DateScheduled date
TimeScheduled time (right-aligned in UI)

Sync rule: row count should equal Interviews This Week KPI when filtered to current week.

Placement timeline (recent activity)

Latest placement movements in scope — applications, interview advances, etc. Newest first.

Each card: event text + relative time.

Pending recruiter responses

Drives blocked waiting on recruiter (JD, slot confirmation).

Formula: jobs with status = IN_REVIEW (or equivalent pending state)

Footer: “Follow up with recruiters to unblock drives”

Intentionally not on this dashboard

  • School performance radar / placement-rate charts
  • Job Opportunities MoM / CR Manager analytics
  • Companies onboarded insight tile (Super Admin territory)
  • Eligible Students duplicate KPI (covered by funnel badge)
  • Application status donut chart

These stay on Super Admin or separate tabs — not the placement officer home screen.
