Admin Dashboard metrics explained

What each number on the real Admin Dashboard tab means — the page rendered by frontend/src/components/dashboard/admin/AdminHome.jsx. Data is fetched live from the backend (polled every 30s).

Primary API: GET /api/admin/dashboard · Job Opportunities block: /api/job-opportunities/*

Scope & filters

Regular admins see a banner: “Viewing your data — assigned center/school only.” Their data is filtered server-side via getAdminScopeFilter() using allowedSchools, allowedCenters, and allowedBatches on the admin profile.

Super admins get an extra filter bar (Campus, School, Batch, Admin) that passes center, school, batch query params to the API.

Important: Job Postings and Companies Onboarded are counted institution-wide (not scoped to the admin's students). Student/application metrics are scoped.

Top row — 4 stat cards

From response.stats in adminDashboard.js. Each card has a mini pie chart.

Card

Job Postings

stats.totalJobsPosted

Formula: count of jobs where isPosted = true OR status = POSTED

Global count — not filtered by admin scope or dashboard filters.

Card

Active Students

stats.activeStudents vs stats.totalStudents (pie denominator)

Active: students in scope where linked user status = ACTIVE

Total: all students matching scope + filters

Scoped to admin's students.

Card

Pending Queries

stats.pendingQueries

Formula: count of studentQuery records with status IN (OPEN, PENDING, UNRESOLVED), filtered to scoped students when a student filter is active.

Student support tickets awaiting admin response.

Card

Applications

stats.totalApplications — pie splits Placed vs Applied

Total applications: all applications where student matches scope

Placed slice: stats.placedStudents — unique students with at least one application where status OR interviewStatus is SELECTED, ACCEPTED, or OFFERED

Applied slice: totalApplications − placedStudents (remaining application count, not unique students)

Note: pie mixes unique students (placed) with total application rows (applied remainder).

Key Insights & Metrics — 4 insight tiles

Computed in AdminHome.jsx from the same stats object. Color tone (green/amber/red) is UI-only.

Companies Onboarded

stats.activeRecruiters

Formula: count of companies that have at least one posted job (isPosted or status = POSTED). Falls back to recruiter count if company table unavailable.

Global — not scoped to admin's students. Subtitle: “With active job postings.”

Placement Rate

UI formula: round(placedStudents / totalApplications × 100)

Subtitle shows: “X placed of Y applications”

This is not the same as the School Performance “Placement Rate” on the radar chart (which divides by total students, not applications).

Tone thresholds: ≥40% good · ≥15% warn · else bad.

Support Queue

Same value as Pending Queries card: stats.pendingQueries

0 = good (green). Any pending = bad (red).

Avg Applications

UI formula: round(totalApplications / activeStudents, 1)

Subtitle: “Per active student (N active)”

Tone: ≥2 good · ≥1 warn · else bad.

Chart

School Performance & Applications (radar)

From chartData.schoolPerformance — one dataset per school in admin scope. School tabs switch the chart.

Performance metrics (%)

  • Placement Rate — placed applications ÷ total students in school × 100
  • Application Rate — total applications ÷ total students × 100
  • Conversion Rate — placed applications ÷ total applications × 100
  • Interview Rate — interview-eligible applications ÷ total applications × 100

Application counts (normalized to % for radar)

  • Total Students — student count in school
  • Applied — application count for school
  • Interview Eligible — applications with screeningStatus = TEST_SELECTED
  • Placed — applications matching placement status filter

Placed uses: status OR interviewStatus IN (SELECTED, ACCEPTED, OFFERED). UI scales application counts to 0–100 using fixed max values (4000 / 1000 / 600 / 100) for radar display.

Returned by API but not shown on dashboard UI

These exist in GET /api/admin/dashboard response but are not rendered in AdminHome.jsx today:

  • stats.blockedStudents, pendingStudents, rejectedStudents — user status breakdown
  • chartData.placementTrend — monthly placement count (last 6 months)
  • chartData.recruiterActivity — top 10 recruiters by jobs posted
  • chartData.queryVolume — student queries grouped by type
