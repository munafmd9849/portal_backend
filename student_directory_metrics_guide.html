Student Directory metrics explained

What each column in the admin Student Directory table means, how it is calculated, and what admins should use it for.

Source: backend/src/services/studentDirectoryMetricsService.js · Planned split documented below (not implemented in app yet)

Planned change

Activation vs CS Status — stop duplicating the same signals

Problem (today): Activation and CS Status both read profile completion, login, and activity score. Admins see two badges that often say the same thing.

Fix (planned): Move day-to-day engagement bands into Activation. Keep CS Status for risk, compliance, and exceptions only.

Activation → owns

  • Highly engaged students (Active)
  • Low engagement band (Inactive)
  • Not yet set up (Not Activated)

CS Status → owns

  • Blocked accounts
  • High Risk (no-shows, long idle, score < 30)
  • Onboarded (moderate score 50–69)
Badge

CS Status

Career Services status — compliance and risk flags. Not placement outcome. Not day-to-day engagement (moving to Activation).

Current (in app today)

  • Blocked — account BLOCKED
  • High Risk — 3+ no-shows or 45+ days without login or activity score < 30
  • Active — profile complete + verified/logged in + score ≥ 70
  • Onboarded — profile complete + score 50–69
  • Inactive — score 30–49 (low engagement)

Overlaps with Activation — same inputs computed twice.

Planned (after change)

  • Blocked — account BLOCKED (unchanged)
  • High Risk — 3+ no-shows or 45+ days without login or activity score < 30 (unchanged)
  • Onboarded — profile complete + score 50–69 (unchanged)
  • Active — removed → moves to Activation
  • Inactive (30–49) — removed → moves to Activation

CS Status = “needs intervention or special case” only.

Badge

Activation

Student engagement on the portal once we split metrics. Replaces the duplicate onboarding + engagement logic currently split across both columns.

Current (in app today)

  • Active — profile complete + (verified or logged in) + account ACTIVE
  • Inactive — anything else (incomplete profile, never logged in, etc.)

Binary onboarding only — does not reflect engagement score.

Planned (after change)

  • Active — profile complete + verified/logged in + activity score ≥ 70 (from CS Status today)
  • Inactive — profile complete + activity score 30–49 (low engagement) (from CS Status today)
  • Not Activated — profile incomplete or never verified/logged in

Score 50–69 → neither Active nor Inactive here; CS Status: Onboarded covers that band. Score < 30 or risk triggers → CS Status: High Risk.

Mock Interviews

Summary of completed mock interview slots that have interviewer feedback. Pulled from mock_interview_slots.

-- — no completed mocks with feedback

72% (example) — one completed mock; shows latest score

1 done — one completed mock without a numeric score

Practice readiness signal — not counted in placement pipeline status.

Badge

Placement Status

Where the student stands in the placement pipeline, based on application records.

Placed — has an offer / selected / accepted application, or statsOffers > 0

In Process — has at least one open application (not rejected / withdrawn / closed)

Unplaced — no open applications and no placement offer

This is the primary “did they get placed?” column.

Number

Jobs Assigned

Count of drives/jobs distributed to this student via job targeting (job_tracking rows). These are jobs the system surfaced or assigned to them — they may or may not have applied.

Formula: jobTracking.length

Number

Eligible Jobs

How many jobs the student could reasonably apply to — the higher of jobs assigned via tracking or jobs they actually applied to. Covers cases where a student applied outside the tracked assignment list.

Formula: max(jobTracking.length, jobsApplied)

Number

Jobs Applied

Total number of applications submitted by the student across all drives (active + closed).

Formula: applications.length (falls back to statsApplied on student record)

Number

Applied (Closed)

Applications that are finished / no longer active — rejected, withdrawn, not selected, or marked closed in the pipeline.

Counts applications where status is REJECTED, WITHDRAWN, CLOSED, or NOT_SELECTED, or pipeline status is CLOSED.

Useful to see how many attempts ended without a current open process.

Number

No-Shows

Number of applications where the student missed a scheduled interview (marked NO_SHOW or ABSENT in application status, interview status, or pipeline sub-status).

3+ no-shows can push CS Status to High Risk automatically.

Number

Unapplied

Jobs the student was eligible for but never applied to. Gap between opportunity and action.

Formula: max(0, eligibleJobs − jobsApplied) — high unapplied count = student not using assigned drives.
